## 점검 방법

- API(`:8765`), worker, web(`next dev :3765`)을 별도 데이터 폴더로 띄우고 `REPLAN_PAID_CALLS_ENABLED=false`, `API_KEY` 미설정 상태로 실행했습니다. 모든 결과는 **LLM 없는 규칙 경로** 기준입니다.
- Playwright(Chromium, 1440×1000)로 화면을 직접 조작했습니다. 각 단계에서 사이드바 활성 항목, 상단 상태 카드, 안내 문구, 오류 상자, 화면 안의 모든 버튼·입력칸·링크를 기록했습니다.
- 여정

  - **B** 같은 흐름을 H02(규제 언급), V08(작업 번호 없는 한국어 통보, 메시지 붙여넣기)로 반복
  - **C** 새 프로젝트 → `REPLAN_demo_inputs.xlsx` 업로드 → 미리보기 → 기준 일정 확정 → E01 메시지 입력 → 분석
  - **D** hero 프로젝트에서 감시 계획 제안 확인 → 항목 수락·제외 → 활성화 → 지금 확인
- 여정에서 쓰지 않은 운영 입력(피드, 공급사 달력, 메일, 알림 채널, 현장 준비, 문서 업로드, 기록 클릭)은 별도로 한 번씩 눌러 결과를 확인했습니다.
- 스크린샷: `docs/ux-audit/before/`(수정 전), `docs/ux-audit/after/`(수정 후).

## 주요 발견 요약

1. **순서가 어긋남** — 사이드바와 섹션 배열이 개요 → 변경 → 일정 → 대응안 → 실행 항목 → 기록 순서라 단계(일정 → 변경)와 반대입니다. 화면 안에는 단계 표시가 아예 없습니다.
2. **기준 일정 연결 뒤 다음 단계로 가는 안내가 없음(사전 보고된 첫 발견)** — hero 기준 일정을 연결하면 일정은 보이지만, 상단 상태 카드의 주요 링크가 다음 단계인 '변경'이 아니라 `#actions`의 **'운영 입력 보기'**로 갑니다. 일정 화면에는 "변경 불러오기" 안내가 없습니다(`before_A_03`, `before_A_04`).
3. **해석을 보지 않고 확인하게 됨** — 변경 카드에 추출된 작업·날짜·확인 질문·L2 사례가 나오지 않고 원문만 두 번(제목·본문) 나옵니다. 이 정보는 CSS로 숨긴 이전 화면(legacy)에만 남아 있습니다.
4. **V08은 막다른 길** — 작업 번호 없는 통보는 patch가 비어 있는데도 '변경 해석 확인' 버튼이 나오고, 누르면 "작업을 선택해 주세요"로 분석이 멈춥니다. 작업을 고를 화면이 없습니다(`before_B_V08_09`).
5. **분석 결과가 따로 떨어져 있음** — 해석 확인 뒤 분석이 자동으로 시작되지만 사용자는 변경 화면에 그대로 남고, 완료 안내나 이동이 없습니다. 무엇보다 **H04의 핵심 수치(통보 지연 21일 + 새로 걸린 공휴일 14일, 영향 작업 목록)**가 숨겨진 legacy 패널에만 있어 대응안 화면에서 보이지 않습니다.
6. **승인·확정 순서를 화면이 강제하지 않음** — '확인 요청 만들기', '승인', '일정 확정' 세 버튼이 동시에 활성화되어 있습니다. 순서를 어기면 `HTTP 409 prepare actions before approval`, `HTTP 409 approval required`가 영문 그대로 오류 상자에 뜨고, 상단 상태는 **"연결 확인 필요"**로 바뀝니다.
7. **상태가 실제 기록과 무관함** — 상단 상태 카드는 변경·분석·승인·확정 뒤에도 계속 "기준 일정 연결됨"입니다. 승인 기록은 화면 어디에도 표시되지 않습니다(API 응답에 없음). 프로젝트 목록은 모든 프로젝트를 "기준 일정 대기 · 변경 없음"으로 고정 표시합니다.
8. **확정 뒤 끝이 없음** — 확정 후 새 일정 버전과 Excel로 이어지는 안내가 없습니다. 실행 항목 화면은 대부분 운영 입력 양식(피드·공급사 달력·메일·알림 채널)입니다.
9. **쓰이지 않거나 연동이 없는 기능이 주 흐름에 섞여 있음** — 메일 연결 메타데이터(저장만), 외부 알림 채널(초안만), 현장 준비 템플릿(성공 안내만 뜨고 화면에 아무것도 안 보임), 숨겨진 legacy 영역의 프로젝트 목록·ID 입력 등. legacy 영역은 `display:none`이지만 DOM에 입력·버튼 152개가 중복 렌더링됩니다.
10. **직접 업로드(C)의 변경 이벤트는 불러올 수 없음** — 미리보기에 "5 events"라고 나오지만 합성 통보 목록은 비어 있습니다(hero 데이터만 동작). E01 원문을 메시지 칸에 붙여 넣어야 분석할 수 있습니다.

## 수정 방향(2단계)

- 섹션·사이드바·단계 표시를 한 배열로 통일: 개요(BRIEF) → 일정(IMPORT) → 변경(DETECT) → 대응안(COMPARE·APPROVE) → 실행(EXECUTE) → 이력.
- 단계 상태는 기준 버전, 최신 변경의 확인 여부, 정식 분석, 승인 기록, 확정 버전만으로 계산합니다. 승인 기록과 버전 이력은 `GET /api/projects/{id}` 응답에 읽기 전용 필드(`approvals`, `versions`)로 추가합니다. 계산·에이전트 로직은 바꾸지 않습니다.
- 화면마다 강조 버튼은 하나이며, 단계가 끝나면 다음 화면으로 안내하거나 이동합니다.
- 연동이 없거나 여정에 필요 없는 기능은 삭제하지 않고 실행 화면 아래 **고급 설정**으로 접고 '미연동'을 표시합니다.

| | 순서 |

- 프로젝트 목록의 단계·요약 숫자·다음 할 일은 각 프로젝트 기록에서 계산합니다.
