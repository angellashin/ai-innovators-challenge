# REPLAN 데모 사용 가이드

프로젝트 작업공간은 6단계를 순서대로 진행합니다. 사이드바와 화면 위 단계 표시가 같은 순서를 씁니다.

| 단계 | 화면(사이드바) | 하는 일 |
| --- | --- | --- |
| 1 BRIEF · 프로젝트 맥락 | 개요 | 프로젝트 정보와 지금 할 일 한 가지 확인 |
| 2 IMPORT · 기준 일정 | 일정 | hero 데모 기준 일정 연결 또는 Excel 업로드·확정 |
| 3 DETECT · 변경 감지 | 변경 | 합성 통보 불러오기 또는 메시지 붙여넣기 → 해석 확인 |
| 4 COMPARE · 대응안 비교 | 대응안 | 영향 내역과 대응안 비교 |
| 5 APPROVE · 조건 승인 | 대응안 | 확인 요청 → 조건 확인 기록 → 승인 |
| 6 EXECUTE · 일정 반영·실행 | 실행 | 새 일정 버전 확정 → Excel 다운로드 |
| (기록) | 이력 | 일정 버전, 승인, 분석 실행, 외부 수집, 알림 |

화면 위 단계 표시의 `완료`와 `지금 할 단계`는 저장된 기록(기준 버전, 확인된 변경, 정식 분석, 승인 기록, 확정 버전)으로만 정해집니다. 각 화면에서 진하게 강조된 버튼이 지금 누를 버튼 하나입니다. 상단 상태 카드의 링크는 다음 행동이 다른 화면에 있을 때만 나타납니다.

실행 방법은 [README의 로컬 실행](../README.md#로컬-실행)을 따르세요. 아래 설명은 LLM 키 없이(`REPLAN_PAID_CALLS_ENABLED=false`) 확인한 화면 기준입니다. 키가 있을 때 달라지는 점은 [마지막 절](#llm-키가-없을-때와-있을-때)에 정리했습니다.

## 공통 시작: 새 프로젝트

1. `http://localhost:3000` → **데모 보기** → **워크스페이스 열기** → **프로젝트 만들기**.
2. 프로젝트명을 입력하고 **프로젝트 만들고 계속**을 누릅니다.
3. 정상: 작업공간의 **일정** 화면이 바로 열리고, 단계 표시에서 `1 BRIEF`는 완료, `2 IMPORT`가 `지금 할 단계`입니다.

## 여정 D — 외부 변화 감시 계획

hero 기준 일정을 연결한 프로젝트에서 진행합니다.

1. 변경 화면 아래 **외부 변화 감시 (선택)**을 펼칩니다. 정상: "감시 제안 33개 중 33개를 아직 결정하지 않았습니다" 안내.
2. **감시 제안 검토·작업 연결 설정**을 펼치고 **남은 제안 33개 모두 수락**을 누릅니다. 좌표와 중단 기준이 필요한 `현장 기상 · …`, 등록 공지 `공지 출처 · …`는 선택에서 **제외**로 바꿉니다.
3. **설정 저장 · 감시 활성화** → "등록된 출처를 주기적으로 확인합니다." 상태가 `주기 감시 중`.
4. **외부 변화 지금 확인** → 공휴일 달력과 작업 날짜가 겹치면 '공개 달력 · 실제 휴무 확인 필요' 변경 카드가 추가됩니다. 카드에서 적용을 확인하거나 보류합니다(이 단계는 인터넷의 공개 공휴일 API를 호출합니다).

협력사 달력 제안을 수락해도 달력이 자동으로 만들어지지는 않습니다. 휴무일은 실행 화면의 **고급 설정 → 협력사 휴무일**에서 입력하며 다음 영향 분석부터 반영됩니다.

## 고급 설정(실행 화면 아래)

데모 흐름에는 필요 없는 운영 연동입니다. 표시 의미: `분석에 반영`(실제 계산에 쓰임), `저장만`, `미연동`(외부 시스템과 연결되지 않고 정보만 저장).

| 항목 | 표시 |
| --- | --- |
| 협력사 휴무일 | 분석에 반영 |
| 공개 피드 | 저장만 |
| 메일 연결 정보 | 미연동 — 자동 수신 없음 |
| 외부 알림 채널(이메일·Slack·Webhook) | 미연동 — 발송하지 않음 |
| 현장 준비 템플릿 | 미연동 — 작업·일정과 연결되지 않음 |
| 다른 프로젝트 열기 | 프로젝트 목록과 같은 기능 |
