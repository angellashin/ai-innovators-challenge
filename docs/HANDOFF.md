# REPLAN 인수인계

## 서비스

REPLAN은 설비 도입 프로젝트의 Excel 일정을 기준으로, 협력사 통보와 외부 공지가 어느 작업에 닿는지 찾아 완료일 영향과 대응안을 계산합니다. 날짜·비용·일정은 결정적 계산기가 계산하고, 에이전트는 통보 해석, 공지와 통보의 원인 연결, 통보에 없던 영향 조사, 확인 질문과 메일 초안을 맡습니다. 사람은 해석을 확인하고 조사를 시작하며, 대응안을 승인해 새 일정 버전과 Excel로 내보냅니다.

## X2 데모 실행

```cmd
scripts\demo.cmd
```

(macOS·Linux: `scripts/demo.sh`) 녹화된 LLM 응답을 재생하는 모드로 별도 스택을 띄웁니다. 키와 비용 없이 에이전트가 동작하고, 화면 위쪽에 "에이전트 켜짐 · 녹화본 재생 중(비용 0)"이 보입니다.

`http://localhost:3000` → 프로젝트 만들기 → **hero 데모 기준 일정 연결** → **변경**에서 `X2 · 대표 데모` 불러오기 → **해석 확인 후 영향 분석** → **에이전트로 숨은 위험 조사** → **P-C도 해당함 · 일정 다시 계산** → 추천 조합 확인·승인 → **새 일정 버전 확정** → **Excel 다운로드**(마지막 완료일 2028-01-25). 화면별 확인 항목과 캡처는 [DEMO_GUIDE.md](DEMO_GUIDE.md)에 있습니다.

## 이번 브랜치에서 바뀐 것

- **에이전트 진단과 개선**: 실제 호출로 H04·H02·V08·외부 신호를 진단하고 31건을 기록(해결 28, 미룸 3). 잠정 분석·자동 감지는 LLM 없이, 정식 분석은 계산이 끝난 대응안을 1회로 설명하도록 줄이고, 옵션 ID 잘림·JSON 노출·틀린 표시를 고침.
- **재생 모드**: `REPLAN_LLM_MODE=live|record|replay`와 녹화본 `data/llm_replay/hero_demo.json`. 녹화 흐름 10개를 비용 0으로 재생(29건, 누락 0), CI 테스트도 녹화본 사용.
- **조사 루프**: 사람이 시작하는 숨은 위험 조사(공지·통보 연결 → 품목 찾기 → 여유 계산 → 조건부 계산 → 확인 요청·메일 초안), 멈춤 사유 M1~M5, 도구 호출마다 '왜' 기록, 사람 확인 후 재계산. WBS 원산지·통관·인허가 열과 Procurement 시트 추가.
- **실제 사례 기반 시나리오**: X2는 RS-019(중국 희토류 자석 선적별 수출 허가, CNBC 2025-10-15), X1-A는 RS-001을 따라 만듦. 기사 속 지연 기간은 계산에 쓰지 않음.
- **화면 정리**: 변경 → 대응안 → 실행 한 방향, 화면마다 진한 버튼 하나, "통보 내용만 반영" 대 "에이전트 조사 후" 비교, 근거·판단 기록·메일은 접음, 추천 대응안 먼저. 협력사 통보 카드 하나에 관련 외부 신호(연결된 공지 + 실제 기사)를 합침. 단계 표시는 보고 있는 결과를 따라감. `scripts\demo.cmd`로 한 번에 실행.

세부 기록: [AGENT_AUDIT.md](AGENT_AUDIT.md)(진단·개선 표), [AGENT_LOOP_DESIGN.md](AGENT_LOOP_DESIGN.md)(루프 설계와 구현 상태).

## 외부 변화 감시가 가져오는 것

'외부 변화 감시 (선택)'는 사람이 제안을 수락하고 활성화해야 동작하며, 감지된 변화는 통보 내용과 계산기로만 정리합니다(에이전트는 사람이 시작할 때만).

| 대상 | 실제로 가져오는 것 |
| --- | --- |
| 날씨 | Open-Meteo 예보(현장 좌표·풍속·강수 기준, 선택한 야외 작업에 연결). 선택 시 과거 기상 통계 |
| 공휴일 | Nager.Date 국가 공휴일 |
| 공식 공지 | 등록한 HTTPS 페이지·RSS. 허용 호스트만(`REPLAN_ALLOWED_SOURCE_HOSTS`, 기본 `environment.ec.europa.eu`), 기본 제안은 EU 환경총국 뉴스 페이지 |
| L2 실제 기사 | 가져오지 않음. 저장소의 정리된 사례 모음(`data/l2_risk_signals/risk_signals.json`)을 로컬에서 검색 |

데모의 N-X2는 실제로 수집한 공지가 아닙니다. 합성 공지를 등록 출처 기록 경로(`environment.ec.europa.eu/news_en` 출처, `합성` 표시)로 넣어 실제 감시와 같은 방식으로 저장·자동 정리되게 했고, 화면에서는 "감시 피드에서 들어온 신호 · 관련 있음"으로 보입니다.

## 한계와 남은 일

- **미룬 개선 3건**: F6 감시 계획 보강 LLM 호출(기준 일정마다 1회, 사용자 결정으로 유지), F12 같은 입력 반복 실행의 도구 선택 편차 미측정, F29 유료 상한이 호출이 아니라 실행 단위.
- **사례 검색**: `search_risk_signals`는 위험 유형 단어(예: `trade`, `permitting`)로만 찾고 자유 문구(예: "중국 희토류 자석 부품")로는 찾지 못함. 에이전트가 직접 실제 사례를 찾아 인용하는 시도는 0건으로 끝나(C2) 되돌림.
- **감시와 데모의 관계**: 데모 공지는 합성이며, 실제 감시가 N-X2 같은 공지를 찾는지는 확인하지 않음. 실제 공지 페이지는 적용 확정이 아니라 검토 대상으로만 다룸.
- **재생 모드**: 프롬프트·도구·입력이 녹화와 다르면 `replay miss`로 멈춤. 흐름을 바꾸면 `scripts/agent_flows.py --mode record`로 다시 녹화해야 함. X1-A는 실제 모델이 조건부 계산 전에 질문하고 멈춤(B13).
- **데이터**: 일정·통보·대응안 비용은 합성이고, 평가 표본이 작아 일반 성능으로 해석할 수 없음. 실제 협력사 메일로의 검증이 남음.
